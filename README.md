# Gem

Medical billing assistant — document upload and structured extraction foundation.

Status: implementation ready for app integration; Gemini SDK integration and
end-to-end device testing are deferred. No live extraction has been verified yet.

The `document extraction` folder contains exactly three implementation files:

- `ScanUpload.tsx`: Expo camera capture, multiple pages and image review.
- `FileUpload.tsx`: native Files picker for PDF/JPEG/PNG, plus the shared review,
  multipart upload, progress, cancellation and structured billing results with source quotes.
- `ocr.py`: FastAPI endpoint using Gemini structured outputs and Pydantic validation.
  Returns billing fields, source quotes, page text and review flags.

## Expo integration

These are components, not a scaffolded application. Expo Go runs React Native;
it does not host Next.js. In an Expo TypeScript project, install:

```sh
npx expo install expo-camera expo-document-picker
```

Copy the two TSX files into that project and render either component on an
active screen (unmount the scan screen when navigating away):

```tsx
import ScanUpload from './document extraction/ScanUpload';
// Or import FileUpload from './document extraction/FileUpload';

export default function App() {
  return <ScanUpload endpoint="http://YOUR_COMPUTER_LAN_IP:8000/ocr" />;
}
```

Use your computer's LAN address, not `localhost`, on a physical phone, with both
devices on the same network. Wrap the screen in your app's safe-area layout.
Both components accept an optional `onComplete(result)` callback to hand extraction
results to the next step. PDF selection shows the filename; image selection
shows a preview. Camera captures are photos, without automatic edge detection
or perspective correction.

## Gemini extraction backend

Install dependencies in a Python virtual environment:

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install fastapi uvicorn python-multipart google-genai pillow pypdf
```

Create a Gemini API key in Google AI Studio and set it on the backend only.
No Document AI processor, Google Cloud project ID or service-account credentials
are needed for this implementation.

```sh
export GEMINI_API_KEY="your-api-key"
export GEMINI_MODEL="gemini-2.5-flash" # optional; choose a model available to your account
python3 -m uvicorn ocr:app --app-dir 'document extraction' --host 0.0.0.0 --port 8000
```

For Expo web, set `ALLOWED_ORIGINS` to the exact frontend origin (for example,
`http://localhost:8081`). Native Expo requests do not require CORS configuration.
Never include Google credentials in the mobile app.

`POST /ocr` accepts repeated multipart `files` fields: at most 10 files, 10 MB
per file, 30 MB total and 15 pages total. Password-protected PDFs are rejected.
The `/ocr` route is kept for compatibility, but now returns structured fields:
provider name, total billed, total adjustments, patient responsibility, currency,
and service rows (date, CPT/HCPCS code, description, charged amount, adjustments,
patient responsibility). Each field has `value`, `page_number`, `source_text` and
`review_reason`. Missing or ambiguous values are null. Amounts use decimal strings
rather than floating-point numbers. Each document also includes `source_file`,
`source_index` (1-based upload order), `pages`, and `review_notes`.

`requires_review` is always true. The server validates the schema and page bounds,
flags missing evidence, malformed dates/codes/amounts, and mismatched line-charge
totals when comparable. It does not confirm billing errors. Both page text and
source quotes are generated by Gemini; matching them is an internal consistency
check, not independent verification. Review the original documents for accuracy.
Each file is extracted separately; multi-page PDFs retain page numbers, while
separately photographed pages retain their own filename/upload index. Cross-file
merging and reconciliation are not performed.

Originals and OCR results are not persistently saved
by application code; multipart uploads may use temporary disk storage and are
closed after each request. Cancelling stops the client request; work already
sent to Google may still complete.

This is a development endpoint: use synthetic bills while integrating. Public
deployment still needs authentication, HTTPS, rate limits and a request-body
limit at the proxy (validation occurs after multipart parsing). Editable field correction, CMS comparisons and calls are subsequent features,
not implemented in this upload slice. Requests that fail extraction return an error
rather than partial results. A Gemini API key and device testing are needed to
verify extraction quality on representative documents.

API references: [Gemini structured outputs](https://ai.google.dev/gemini-api/docs/structured-output)
and [document understanding](https://ai.google.dev/gemini-api/docs/document-processing).
